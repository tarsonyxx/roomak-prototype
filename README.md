>This repository is for a student research project: A proposed web-based room scheduling and information system for the University of Makati (UMak).
>
> ## About
>
>RooMak aims to make room-related information and processes easier to access in one place. The prototype demonstrates how users can find rooms on a floor plan, see which ones are free at a chosen time, view room details and schedules, submit room requests, and report room-related concerns.
>
>It is a working prototype built for the sake of research, not a production system for UMak. Room details, schedules and reports are sample data for demonstration unless verified separately.
>
>**Live demo:** https://tarsonyxx.github.io/roomak-prototype/

## Features

- **Floor Plan** — Interactive map of Building 2, the Bridgeway and Building 3 (floors 2 to 4). Drag to move, pinch or use the buttons to zoom.
- **Availability by Time** — Pick a floor, day and time range, and every room is colored: green is available, yellow is unavailable or under maintenance, red is in use, and grey rooms cannot be reserved.
- **Room Information** — Tap a room to see its photo, capacity, facilities, current availability and its schedule for each day.
- **Room Requests** — Request a room for one time, on a recurring schedule, or as a long-term assignment, with a message to the scheduler. The request form starts with the day and time range you were viewing.
- **Schedule Conflict Checks** — If a room is already in use at the chosen time, a pop-up explains the clash and suggests free time slots. Requests for unavailable times, rooms under maintenance, non-reservable spaces, Sundays, or hours outside 7:00 AM to 8:00 PM cannot be submitted.
- **Room Reports** — View issues already reported for a room and report a new one.
- **Light, Dark and Auto Themes** — New visitors follow their device's setting. It can be changed in **Settings**, which also has a button to clear saved data.
- **Account and Settings** — Buttons beside Log out for account details and preferences.
- **First-Time Tips** — A short guided tour for new users. The **?** button replays it.
- **Mobile Friendly** — Built phone-first, with the room panel covering the map on small screens. Images are compressed and animations kept light so it runs on low-end phones.
- **Link Preview** — Sharing the site on Facebook or Messenger shows a branded preview card and tab icon.

Still planned: a feedback form link, role-based views (teacher, scheduler, student), shared data storage, and real accounts.

Features may be simplified or simulated to fit the prototype's development timeline.

## Technology

- HTML for page structure
- CSS for styling and layout (all light and dark colors live in one palette block in `css/base.css`; `css/theme.css` holds the blue-and-gold styling on top of it)
- JavaScript for the floor plan, availability, schedule checks, requests and reports
- Browser `localStorage` for saving requests, reports, tips and the theme choice on the user's own device

No frameworks or build tools are used. The floor plan is generated by JavaScript from the room data in `data/rooms.js`, and class schedules are in `data/schedules.js`.

The prototype does not provide shared, multi-user data storage or real-time room occupancy information. Requests and reports are saved only in the browser they were made in, and nothing is sent to a server. Availability is checked against the sample class schedule only, so two people can still request the same free slot.

```
css/                  base.css (palette), components.css, theme.css, pages/*.css
js/                   floorplan.js, dashboard.js, room-actions.js, hints.js, settings.js, auth.js
data/                 rooms.js (floors, room info, closed rooms), schedules.js (class schedules)
assets/images/        Logo, icons, link-preview image, backgrounds, room photo
```
